# 集群分组、批量终端与命令执行设计（第一版）

日期：2026-11-03
状态：待用户审阅；仅设计，未实施。下文标注的默认值属于本版建议。

## 目标与范围

用户希望把同一集群的机器放入类似文件夹的分组，批量导入后统一管理；既能从界面批量打开终端、执行命令，也能通过内置助手和外部 MCP 完成这些操作。

首版覆盖单层集群、成员管理、导入归类、集群终端工作区、终端命令广播、可追踪的批量命令任务及共享 MCP。暂不做嵌套文件夹、跨机器文件同步、集群安装编排、分布式训练启动参数生成。执行相同命令不代表软件会自动配置分布式训练。

## 现有能力与实现方向

已检查的源代码包括 frontend/src/main.tsx、ServerImport.tsx，以及 backend/terminal_workspace.py、command_tools.py、mcp_service.py、store.py。

机器列表目前是平铺列表，Excel 导入有预览与后台进度。终端使用现有持久会话与交互通道。单机命令已有 execute_server_command、get_command_job、cancel_command_job，使用远端 supervisor 管理任务，并支持输出分页、超时、取消和 sudo。内置助手与外部 MCP 使用同一能力目录，内置调用受服务端机器范围约束。

新增集群业务服务和批次调度；界面、HTTP、MCP 共用服务。命令执行逻辑抽取为可复用服务，避免集群功能绕过现有单机校验。本文描述现有代码能力，不代表本次已进行运行验证。

## 机器列表与归类

建议每台机器只能属于一个集群，未分配机器显示在“未分组”。空集群允许保留。集群名称去除首尾空白，长度 1–80 字符，忽略大小写后唯一；机器标识继续使用现有 host_id。

左侧列表示例：

```text
机器列表                         ＋ 新建集群
搜索机器或集群…
全部  GPU  NPU

▾ □ A2 训练集群                 3 台 · 在线 2
    □ A2-四机-1
    □ A2-四机-2
    □ A2-四机-3
▸ □ H200 集群                  4 台 · 在线 4
▾   未分组                     2 台
    □ server-177-via-jump
    □ 4090-4
```

箭头只控制展开；点击集群名称查看该集群设备；复选框批量选择当前搜索和设备分类下的匹配成员，部分选中显示半选。集群菜单中的“打开终端”和“执行命令”默认针对整个集群，在操作面板中明确列出目标，避免把筛选误认为执行范围。在线数量是监控参考，不作为能否建立 SSH 的最终判据。

名称旁菜单支持重命名、管理成员、打开集群终端、执行命令、删除集群。勾选已有机器后可“移动到集群”。删除集群只解除归类；移除机器沿用现有移除流程。已有任务使用自己的目标快照，不随归类变化。

搜索同时匹配机器和集群名称：命中集群名称显示该集群符合设备分类的所有成员；命中机器显示所属集群和匹配机器。搜索时临时展开，清除后恢复折叠状态。列表数量注明匹配数与总数。分组与成员关系保存在后端；折叠状态作为界面偏好保存，不进入业务权限判断。

## 批量导入

Excel 预览增加“导入到：未分组 / 已有集群 / 新建集群”。首版每批指定一个集群，不增加 Excel 必填列。单机添加也提供可选集群。

导入开始时固定 cluster_id。新增成功的机器立即归组；失败项不产生成员。匹配到已有机器且仅补存密码时，默认不改变原归属，界面明确说明。若目标集群在开始前被删除则拒绝开始；导入进行中删除目标集群返回冲突，结束后再删除。重命名不影响导入。空集群可供失败后重试使用。

## 集群终端工作区

“打开集群终端”进入应用内工作区，每台机器对应独立终端标签页，可查看连接中、已连接、失败状态。建议默认一次最多并行建立 5 个连接，首版一个操作最多 100 台；不是弹出 100 个系统窗口。

后台逐台创建本次专用的持久会话，不向已有会话盲目注入命令。缺少持久终端依赖的机器单独显示失败，不擅自安装依赖。切换标签后再建立可视 WebSocket，避免为所有标签同时维持终端渲染通道。关闭工作区不结束远端会话；明确“结束会话”才执行终止操作。

提供“命令广播”输入框：选择目标终端，输入完整命令，点击“发送并执行”，逐台提交命令和回车。默认关闭同步键盘输入，不逐键广播。首版仅允许向本工作区创建且已确认处于 Shell 提示符的会话发送；忙碌、状态不明、断开的会话直接跳过并说明原因，不能只依靠终端画面猜测就绪状态。需要增加与当前会话绑定的 Shell 就绪事件；无法可靠检测的 Shell 标记“不支持广播”，仍允许手动交互。

广播结果只报告“已发送 / 跳过 / 发送结果不明”，不把发送当作命令成功，也不承诺准确退出码和独立输出。命令可能执行后立即改变终端状态，因此发送结果不明时不自动补发。需要准确跟踪的操作使用下述批量命令任务。

## 批量命令任务

集群菜单“执行命令”打开面板，展示集群名称、全部目标机器、可取消的机器勾选、命令、绝对工作目录、超时和 sudo 开关。默认普通用户、超时 300 秒、并发 5，可设并发 1–10。超时范围沿用现有单机能力。没有跨机器同时启动保证；互相依赖的步骤不属于首版。

点击执行即为本次提交，不再增加第二个通用确认弹窗。后端原子创建批次及每台机器的目标记录，固定成员、连接身份摘要、命令、cwd、sudo、超时和执行选项。客户端提交 request_id，重复提交返回原批次；同一 request_id 携带不同内容返回冲突。

列表按机器展示排队、启动中、运行中、成功、失败、取消中、已取消、超时及结果未知；选中一台读取其 stdout/stderr、退出码和更新时间。命令面板使用远端任务服务，不向用户正在操作的终端注入字符。可提供“打开该机器终端”入口，但不能暗示远端任务正在这个交互会话前台运行。

每台机器独立执行，一台失败不阻止其余任务。不因监控离线直接跳过，实际尝试 SSH 并显示连接错误。cwd 不存在直接失败；不自动创建目录、不自动提权。所有机器收到相同命令，首版不提供变量模板替换。

“停止批次”阻止尚未启动的成员，并取消已经启动的任务。沿用单机 TERM 后 KILL 的语义；请求取消不等于已停止，断线时保留结果未知。取消不会回滚已发生的副作用，脱离进程组的后台程序仍受现有能力限制。

“重试”需要用户主动发起一个关联的新批次，只能选择已确认终止的失败、超时或取消项；面板提示重试可能重复已有副作用。成功项不默认重跑；结果未知和仍运行项不允许直接重试，先查回状态。禁止自动重试启动结果不明的命令。

## 持久化、重启与输出

建议使用 SQLite 独立表：clusters、cluster_members、cluster_batches、cluster_batch_items。成员关系对 host_id 唯一；集群与成员更新在同一事务中完成。采用 revision 乐观锁，避免多个窗口或助手相互覆盖。现有机器首次升级均为未分组，不修改 SSH 配置。

批次成员存储 host_id、目标显示名称、连接身份摘要、预分配 remote_job_id、状态、错误、退出码和时间。SSH 账号/地址/端口等执行身份改变后停止新派发，查询和取消报告身份冲突；不在新的连接目标上盲目查询同名任务。凭据与密钥不入批次记录。

启动前持久化远端 job_id，并让单机服务接受内部预分配 ID。后端重启后，对启动中或运行中任务用原 ID 查回，禁止再次启动；无法证明是否启动成功则保持未知。排队项在重启后暂停，用户主动“继续未启动项”才继续派发。删除机器、集群或修改分组不级联删除任务记录，也不自动停止任务。

输出沿用单机当前限制：每流最多保存前 1 MiB，读取分页，有截断提示；远端 /tmp 被清理后可能无法再读取，明确显示输出不可用。首版本地仅持久化批次元数据和终态摘要，不把临时输出宣传为永久日志。建议终态记录保留 30 天，运行中与未知记录不自动删除；可手动删除终态历史。命令正文会保存在本地历史，界面提示不要在命令中填写明文凭据；不在列表摘要和普通事件日志中展开正文。

## HTTP 与 MCP

建议 HTTP 资源：/api/clusters（列表、创建）、/api/clusters/{id}（读取、更新、删除）、/api/clusters/{id}/members（成员修改）、/api/cluster-batches（启动、列表）、/api/cluster-batches/{id}（状态）、其 items/{item_id}/output 与 cancel 子接口；终端批次独立使用 /api/cluster-terminal-batches。参数模型统一生成 MCP schema。

建议 MCP 工具：

| 工具 | 用途 |
| --- | --- |
| list_clusters / get_cluster | 查询集群及范围内成员 |
| create_cluster / update_cluster / delete_cluster | 创建、重命名、删除分组 |
| update_cluster_members | 明确添加、移出或移动成员，携带 revision |
| open_cluster_terminals | 创建一批专用持久会话并返回打开入口与逐机结果 |
| execute_cluster_command | 提交相同命令，返回 batch_id 与固定目标 |
| get_cluster_command_batch | 分页读取逐机状态与汇总 |
| get_cluster_command_output | 指定 batch、item、stream、offset 读取有界输出 |
| cancel_cluster_command_batch | 取消整个批次或明确指定的成员 |

MCP 创建会话与客户端实际打开界面分开表示：没有接入的界面时返回“会话已创建，等待打开”，不能声称窗口已经打开。内置助手可返回可点击的工作区入口；外部客户端获得交接信息。MCP 的执行操作使用可追踪命令任务，不依靠终端广播取得结果。

内置助手：集群查询只返回 allowed 范围内成员；范围受限时明确“仅显示当前允许的机器”，不泄露范围外机器名称和数量。执行默认要求整个目标集群都在 allowed 内，否则报范围冲突，调用方可显式指定已授权 host_ids 子集，不能默默执行交集却报告整个集群完成。提交同时携带期望 revision，成员变动返回冲突，要求重新读取目标；检查与快照创建必须原子完成。

集群级重命名、删除和成员变更，受限会话必须拥有相关集群全部成员及所有涉及机器的范围，否则拒绝，避免隐藏成员被间接改变。新建集群与读取空集群在本地可信边界内允许。任务状态、输出、取消逐项重新检查 allowed，未经授权的成员既不返回也不操作；只有拥有全部批次目标范围时才允许取消整个批次。

外部 MCP 延续现有本机服务信任边界，不因增加集群工具引入多租户权限承诺。所有操作继续校验参数、目标、凭据和用户授权；服务器输出、文件或技能内容不能扩大授权。此处不新增所有操作都必须弹窗确认的审批层。

## 交付顺序与验收

1. 分组持久化、机器列表、已有成员移动和导入归类。
2. 批次调度、重启恢复、结果界面及命令 MCP。
3. 集群终端工作区、可靠就绪检测和显式命令广播。

以上是一个完整功能的实施顺序，最终交付包括三部分。每部分复用现有语言、框架与 SSH 通道，不新增第三方终端服务。

验收覆盖：旧数据无损升级；分组增删改与并发冲突；搜索分类与半选一致；导入新增和已有机器归属；部分连接失败；重复提交去重；启动后断线、重启不重复执行；停止排队与运行项；输出截断及缺失；sudo 凭据不泄露；变更连接身份拒绝误操作；MCP 跨范围读取/修改/取消被拒绝；内置与外部目录一致；终端广播跳过忙碌或未知会话。

单元与接口测试使用隔离数据库和假 SSH；端到端使用专门的测试机器或 WSL 执行 printf、sleep、非零退出和取消，不对真实训练进程做验收。UI 验证包含中英文、空集群、大列表、部分失败及重复点击。

## 本版需要用户审阅的主要取舍

- 单层分组，每台机器归属一个集群。
- 批量打开终端采用应用内多标签工作区。
- 保留显式终端广播，同时用独立任务提供可靠的执行记录。
- 首版同一命令与工作目录发送给全部所选机器，不做主节点/工作节点编排。
- 默认并发 5、最多 100 台；远端任务输出有界，本地不长期缓存输出。

其余布局、模块命名和实现细节由实施阶段根据现有代码决定。用户审阅通过后再形成实施计划，本文不代表已开始修改产品代码。

## 实施补充（2026-11-04）

现有 Shell 协议能证明最近出现过提示符，但不能可靠证明交互断开后的 readline 缓冲区为空。首版采用保守规则：终端工作区不自动接入显示通道；手动接入过的专用会话永久退出该工作区广播集合。未接入的会话仍需通过认证提示符、无附着客户端等检查。需要持续批量操作时优先使用可追踪命令任务。这是实施中确认的能力限制，避免向半行输入追加命令。
