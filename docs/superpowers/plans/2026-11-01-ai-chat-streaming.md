# AI chat: actual streaming

User requirement: responses should arrive continuously like Codex/Claude instead of a spinner until the whole prompt finishes. Existing Python/React UI, Windows and macOS, existing provider settings. Stop the previous broad AI verification task; validate only the new streaming behavior.

Design: true provider SSE for Responses and Chat Completions, incremental server-to-browser SSE over same-origin fetch, retain read-only tool validation/scope, cancellation and durable conversations. No fake typing animation and no new credentials or endpoints outside the configured provider.

Protocol contract:
- Provider: `AgentAPIService.turn(instructions, messages, tools, *, on_text=None)`. Callback is synchronous and receives accumulated text for this single model request. Existing calls without callback remain compatible/nonstream. Streaming must assemble and validate complete native tool calls before returning the existing normalized response shape. Transport errors/EOF cannot mark a partial response successful.
- `GET /api/assistant/chats/{id}/events`: SSE `snapshot` data is existing `Chat`; `turn` data is `{chat_id, title, updated, active_run, turn}` where `turn` is the replacement latest assistant `ChatTurn`; optional `deleted` data `{chat_id}`. Snapshots and turns include no model messages/private state/credentials. Initial snapshot on each connection; final turn has active_run:null. Heartbeats are comments. Closing subscription does not cancel server work; explicit cancel endpoint does.
- Text changes are coalesced around40–50ms, retained in active memory and checkpointed around250ms (not a SQLite transaction per token). Tool transitions publish immediately. Event wakeups bounded/coalesced; reconnect starts from fresh snapshot.
- Frontend applies snapshots or latest-turn updates only for current chat/run, reconnects via snapshot, aborts on chat switch/unmount, retains explicit cancel. Follow newest text only when reader remains near transcript bottom. Preserve history, machine scope and per-tool UI. Do not write localStorage every token.
- Stream output must not leak configured API key split across chunks, incomplete quoted credential values or private-key blocks. Completed output retains existing scrub behavior.
