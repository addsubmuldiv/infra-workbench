# Infra Workbench MCP Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline. Subagents are unavailable in this side conversation.

**Goal:** Replace the CLI with a discoverable six-tool HTTP MCP interface for local and remote agents.

**Architecture:** Official Python MCP SDK mounted at /mcp in the existing FastAPI backend. AgentService shares current inventory, bounded sampling, SSH descriptors and saved SSH credentials. Tools advertise complete schemas, examples and structured recovery steps.

**Tech Stack:** Python 3.11+, official mcp SDK, current FastAPI/AsyncSSH, existing React GUI.

**Spec:** ../specs/2026-10-31-infra-mcp-design.md

## Global constraints
- Same loopback listener and same GUI; no new account/token platform or command forwarding.
- Six tools only: list_hosts, search_hosts, get_host, get_resources, get_ssh_info, get_ssh_password.
- Search defaults idle=true; unknown/stale/Alarm cannot masquerade as available resources.
- No credentials in tool discovery, instructions, ordinary results or logs. Only explicit get_ssh_password returns a secret.
- Preserve existing password GUI/storage; user explicitly authorized CLI removal. No commit/push requested.

## Review focus
- Standard MCP clients must work without the private X-IWB header, while existing GUI origin/header checks remain.
- Mounted SDK transport requires its session manager lifespan; protocol/client versions must interoperate.
- Partial errors retain valid data; error recovery names MCP tools and valid arguments, not removed CLI commands.
- Multi-die, mixed-kind, duplicate aliases, jump keys, native argv and credential identity coverage survive migration.
- Actual remote MCP calls must go through existing proxy despite loopback bypass defaults; HTTP 200 alone is insufficient.
