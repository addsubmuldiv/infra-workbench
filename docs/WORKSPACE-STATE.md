# 共享工作空间状态

界面状态统一保存在本机 `data/workbench.db` 的 `config` 表（`workspace_ui_state_v1`）。浏览器只保留当前渲染使用的内存副本。普通浏览器、内置浏览器及桌面 WebView 连接同一个后台时，使用同一份状态。

覆盖主题、选中机器、筛选与搜索条件、设备选择、当前页面、助手展开状态和窗口布局、当前聊天、聊天草稿和显式技能选择、助手页签、侧栏/终端/命令窗口尺寸、通知已读位置、预约等待偏好及精度对比草稿。远端 SSH 连接、DOM 引用、拖动中的坐标、请求控制器、密码输入等属于运行时状态，不写入界面偏好，也不会因为另一个窗口打开页面而自动新建 SSH 连接。

- `GET /api/workspace-state` 返回 `{revision, values}`；响应禁止缓存。
- `PUT /api/workspace-state` 提交 `{values: {key: string | null}, only_missing?: boolean}`；null 表示删除。沿用本机 Origin 和 X-IWB 检查。
- 后台只修改提交的键，其他键保留；同一个键以最后到达后台的写入为准。每次有效更改增加 revision。
- 每项最多 64 KiB，整个状态最多 512 KiB、256 项，单次最多 128 项。仅接受工作台状态命名空间。
- 前端操作立即更新内存，250ms 合并保存；其他客户端每 1.5 秒读取一次。断线保留尚未保存的改动，恢复后重试；保存失败有提示，关闭前会提示未保存。
- 初次加载先从后台恢复，再渲染应用。后台不可用时显示重试入口，不用浏览器旧值冒充后台状态。
- 旧版本 localStorage 仅在迁移阶段读取。只补后台缺失项，后台通过后移除旧键。后续没有 localStorage/sessionStorage 写入。
- 窗口尺寸共享，但展示时仍按当前屏幕大小限制位置和宽度。操作系统通知权限由操作系统/浏览器管理，不属于可同步的应用偏好。

首次使用引导的完成状态使用 `workspace:onboarding-completed:v1`，值为 JSON 布尔值。新工作空间成功读取状态且尚无机器时自动展示；完成、跳过或 Escape 后置为 true。已有机器的工作空间首次加载该功能时直接记为已处理，避免升级打断使用。重播只打开当前窗口的引导，不清除共享完成状态；演示模式及独立工具窗口不挂载正式版引导。

验证：后端持久化/重启恢复、逐键合并、迁移不覆盖及输入限制；前端两个独立存储客户端同步、保存中的新编辑、断线重试与迁移覆盖保护。实机通过 `127.0.0.1` 与 `localhost` 两个独立站点存储页面验证机器选择、聊天草稿和主题一致。

资源刷新间隔通过独立的 `/api/settings/refresh` 设置，保存在数据库 `refresh_interval_seconds` 中，后台采集、页面和浮窗共用。未设置或恢复默认时，使用 `config/internal-defaults.jsonc` 的 `monitoring.refresh_interval_seconds`；该配置通过生成脚本供前后端引用。手动选择优先于默认值，提交 `interval_seconds: null` 清除手动覆盖，立即恢复默认并在重启后继续跟随默认值。修改配置文件后需重新生成、构建并重启后台。

助手权限模式、本机/远端工作目录和可选外部 MCP 服务地址也使用 workspace:chat-* 键共享。它们只影响下一轮请求；待批准调用、批准 Future 和执行中的连接不写入偏好，而由本轮服务端控制器持有。批准记录保存到聊天历史，页面关闭和 SSE 重连不视为批准。
