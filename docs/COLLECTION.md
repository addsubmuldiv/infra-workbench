# 采集调度与性能统计

后台以用户配置的刷新间隔为目标周期，将当前全部机器均匀放入时间槽。机器集合或间隔变化时重新分配，不假定固定机器数量。全局错峰也会分散共享跳板的请求，不额外降低单个跳板的并发上限。

- 使用单调时钟调度；成功后回到下一个未来时间槽，不将采集耗时累加到周期里。
- 全局最多同时采集 8 台，每台最多一项在途采集。定时采集、HTTP 和助手/MCP 复用同一任务。容量不足时排队，错过的轮次不补跑，不偷偷修改用户配置。
- 失败后采用带随机抖动的指数退避，最长 120 秒；调整机器集合不会取消失败退避。
- 系统、设备、设备进程列表及监听端口每轮采集，继续供预约判断。失败、缺失和过期数据保持未知。

## 分层详情

`tmux`、全机 PID/用户列表，以及普通用户可见的进程命令行、目录、可执行文件约每 60 秒采集。快采集仍读取当前用户并核对进程启动 ticks；只有机器启动标识一致、身份核对成功且 ticks 相同时才复用详情，保留原详情采样时间。新 PID 或身份不明时不套用旧详情。

同一个进程也可能在两次详情采样间执行 exec 或切换目录，缓存详情不能代替进程操作前的实时检查。已启用的 sudo 详情补充仍每轮验证和采集，不缓存提权结果。手动刷新新建任务时请求完整详情；已有任务正在进行时复用其结果。

## 界面与统计

机器卡片显示等待、采集中、手动刷新完成/失败，以及上次耗时、排队时间、探针返回大小。展开统计可查看后台启动以来的采集次数、累计返回字节数和实际采集间隔。

耗时包含连接、探针、解析及 sudo 补充，不含队列等待。字节数只统计探针命令、上传源码和 stdout/stderr 的 UTF-8 大小，不含 SSH 协议、跳板、sudo 补充及其他业务请求，不能当作网卡流量。

批量刷新只处理当前所选机器，显示完成数和失败数；客户端最多同时请求 8 台，服务端沿用采集去重与并发校验。演示刷新只更新内存模拟状态。

前端按机器 ID 复用未变化对象，卡片按自身数据和选择、筛选条件跳过重复渲染。新增、删除或重排其他机器不会破坏未变化机器的对象引用。状态接口仍返回完整数据，此次没有新增增量传输协议或列表虚拟化。

## 验证与生效

调度测试覆盖 1、16、100、1000 台及全部可配置周期，并检查跳过过期轮次、失败退避和动态调整。隔离数据测试覆盖采集合并、字节统计、PID 复用保护和快采集省略重字段；前端测试覆盖手动刷新反馈及机器重排时的引用复用。

后端更新需要重启后台。重启前检查当前终端和任务；测试、构建通过不代表真实共享跳板承载能力或流量降幅已经实测。
