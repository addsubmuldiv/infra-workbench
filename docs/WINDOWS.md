# Windows 安装与使用

## 桌面安装包

从[最新 Release](https://github.com/addsubmuldiv/infra-workbench/releases/latest) 下载 Windows x64 向导安装包。安装包包含 Python 后台及前端资源；普通用户无需安装开发环境。附件中的 `SHA256SUMS.txt` 用于检查下载完整性，具体包含的功能以该版本的 Release 说明为准。

桌面版仍需要 Windows 的 OpenSSH 客户端（`ssh.exe`、`ssh-keygen.exe`），用于交互终端、SSH 配置解析和免密验证；它不随 Python 后台打包。可在 PowerShell 运行 `ssh -V` 检查，缺失时在 Windows「设置 → 可选功能」中安装 OpenSSH 客户端。

安装程序尚无 Authenticode 代码签名，更新文件另有更新签名。构建与冻结后台自测不能替代无 Python / Node.js 的干净 Windows 系统安装、升级和卸载验收。

以下 `安装.cmd`、Python、WinGet 和保留项目目录等要求适用于源码安装。不要把源码启动器生成的 EXE 当成可独立分发的桌面安装包。

当前代码为全新的空工作空间提供首次使用引导，完成或跳过后记住状态；已有机器的工作空间不会在升级时被强制打断。可在「设置 → 关于与帮助 → 重播新手引导」手动打开，完整流程见[首次使用](GUIDE.md#首次使用与新手引导)。

## 源码安装适用环境

- 本机：Windows 10 / 11，Windows PowerShell 5.1 或更高版本，具有写权限的普通目录。
- Python 3.11+，Windows OpenSSH 客户端 `ssh.exe`。
- 首次安装需要访问 Python 包源；Python 缺失时还需要 WinGet 及其下载源。
- 服务器：Linux、Python 3、`nvidia-smi` 或 `npu-smi`；端口检查需要 `ss`。
- 不需要管理员身份，也不需要在远端安装常驻服务。普通用户使用附带的前端构建，无须 Node.js。

不要直接在 ZIP 预览窗口里运行，不要放在 Program Files 等受保护目录，也不要放在多人共享或自动同步的目录：`data` 可能包含专用 SSH 私钥。

## 安装与日常启动

第一次使用：完整解压仓库，双击根目录的 **`安装.cmd`**。它会安装依赖、生成图形启动程序和桌面快捷方式，并自动打开软件。以后双击桌面的 **Infra Workbench** 图标即可。请保留项目文件夹，快捷方式依赖其中的文件。

默认打开浏览器界面。进入「设置 → 启动与桌面浮窗」，可以改为桌面窗口；启动时只打开其中一种。桌面浮窗默认开启，也可在设置或托盘菜单关闭。

已有依赖时，启动程序只运行隐藏的 Python 后台和选中的图形界面，不创建命令行窗口。首次缺少依赖、依赖版本更新或前端缺失时，才打开安装窗口；安装成功后继续启动选定界面。安装失败会显示图形错误提示，可检查数据目录中的 launch.log 与 desktop.log。

`安装.cmd` 是 `install.cmd` 的中文入口，两者执行同一套安装流程；重复运行也会重新生成启动程序和桌面快捷方式。`install.cmd -NoLaunch` 可只安装，`install.cmd -Repair` 用于修复依赖。内部 start.ps1、background.ps1 仅供排障，不再是日常入口。

关闭网页或桌面窗口后，托盘继续采集，浮窗也可继续显示。退出托盘才会停止后台。已有托盘会复用，不启动第二套后台，不清空机器、规则或主题。

进入“添加机器”，可从 `%USERPROFILE%\.ssh\config` 及 Include 文件导入别名，也可以手动填写。每位同事使用自己的账号、SSH 配置和授权，不要复制你的 `data` 给别人。

新机器首次连接时，先在 Windows 终端执行 `ssh 别名`，或 `ssh -p 端口 用户名@主机`，核对并信任主机指纹，再回到软件连接。指纹变化需先核实原因。

## 更新与修复

更新前先保存文件编辑内容，并妥善结束或保留网页 SSH 终端中的任务。托盘模式从托盘菜单退出并停止后台；控制台模式在原服务窗口按 Ctrl+C。若托盘接入的是已有服务，还需要停止原来的服务入口。

- Git 用户：执行 `git pull --ff-only`，再双击 `安装.cmd`。
- ZIP 用户：解压新版本到新目录。需要迁移机器与规则时，由本人把旧版 `data` 复制到新版相同位置，不覆盖自己的 SSH 配置。不要把它加入分享包。
- 在原目录更新且保留 `data` 时，机器与规则继续保留。浏览器偏好与访问地址、浏览器有关。

只刷新网页、关闭网页或重复双击启动文件，会继续使用已有后台，不能替代重启。重新启动后台后，再刷新网页加载新界面。重启会结束普通 SSH 终端连接；tmux 持久会话仍留在远端，可从终端加号菜单恢复。

持久会话中的增强脚本在创建时加载。要使用本次更新的完成记录队列，请在更新并重启后台后新建持久会话；已有会话可以继续使用，待任务结束后再更换。详见 [tmux 持久会话](TERMINAL.md#tmux-持久会话)。

强制重新检查并安装依赖：

```powershell
.\install.cmd -Repair -NoLaunch
```

`-Repair` 会重跑 pip 安装与检查，不清空数据；若 Python 被卸载或 `.venv` 本身损坏，停止服务后把 `.venv` 改名备份，再运行安装。不要移动已经创建虚拟环境的整个目录后直接继续使用：虚拟环境依赖原 Python 路径。

## 常见问题

| 现象 | 处理 |
|---|---|
| 找不到 Python / WinGet | 安装 [Python Windows 版](https://www.python.org/downloads/windows/)，建议 3.12，并启用 Python Launcher，然后重试。公司策略禁用安装时联系管理员。 |
| 找不到 ssh.exe | 在 Windows“设置 → 可选功能”中检查 OpenSSH 客户端；安装系统可选功能可能需要管理员。部署脚本不会自动修改系统功能。 |
| pip 下载失败、证书或代理错误 | 根据窗口错误检查网络、公司 CA 和 pip 代理配置后重试；不要关闭 TLS 验证。企业镜像可先在本机设置 `PIP_INDEX_URL`。 |
| 安装停在中间 | 保留报错，修复后重复运行 `install.cmd`；失败不会留下成功标记。 |
| 8765 被其他程序占用 | 先确认占用者，关闭对应应用后重试。脚本不会自动杀进程。 |
| 浏览器没有自动打开 | 手动访问 <http://127.0.0.1:8765/>，检查启动窗口是否已出现服务日志。 |
| 终端能连接、软件不能 | 先确认 Windows 原生 `ssh 别名` 可连接；WSL、其他终端软件的独立密钥库不一定与 Windows OpenSSH 相同。 |
| 进程路径显示权限不足 | 这是远端读取权限问题，和能否 SSH 登录不同；普通采集仍可使用。 |
| 缺少前端构建 | 使用完整分享包；开发者可安装 Node.js 24，运行 `install.cmd -RebuildFrontend -NoLaunch`。 |

## 备份与卸载

停止服务后，按需自行备份 `data`。其中数据库保存机器和规则，`data/keys` 可能保存专用私钥，备份应妥善保管。

删除项目文件夹即可移除项目环境，不会卸载系统 Python 或修改原有 `.ssh/config`。如果启用过自动免密，删除项目不会撤销服务器上的公钥，需要本人核对后撤销相应 `authorized_keys` 条目。若使用过“记住 sudo 密码”，先在软件中删除相应已保存密码；Windows 凭据不在项目文件夹中。

## 启动耗时

启动前使用 100ms 上限的本机 TCP 探测判断端口是否开始监听，端口存在后仍校验完整 HTTP 健康响应。这样避免 Windows 上不存在的服务每次花约两秒等待连接失败。模型框架在首次执行 AI 对话时加载，不阻塞资源总览首屏；第一次对话可能需要额外初始化时间。`data/launch.log` 记录界面打开前的等待耗时。

隔离测试命令：`.venv\Scripts\python.exe scripts/benchmark-cold-start.py`。测试使用临时数据和临时端口，不停止当前后台；结果只代表后台 HTTP 就绪，不包含浏览器 / WebView 打开及远端首次采集。
