# AI 对话流式输出验证

日期：2026-11-01。分支：`ai-chat-streaming`，基于已合入 main 的 AI 助手实现。

## 实现

- 模型请求使用真正的 `stream:true`，支持 Responses 和 Chat Completions 的文本增量及原生工具调用参数拼接。
- 后端通过同源 SSE 推送初始快照、当前助手消息和完成状态。文本更新约40ms合并一次，生成中的内容约250ms分批保存；工具状态立即唤醒订阅。没有逐 token 写数据库或每次发送整段历史。
- 前端取消原先850ms轮询，实时替换当前助手消息。断流重连读取新快照；切换会话和卸载时中止显示订阅；取消按钮仍显式取消服务端任务。
- 只在读者靠近对话底部时跟随新增文字，不自动拖动外层页面。工具调用前已生成的说明会保留。
- 分段文字、最终文字和持久化内容共用脱敏规则。工具参数完整且通过校验后才执行。未完成或中断的流不会标记成功。

## 一条真实模型请求

用户正常退出托盘后台后，重新使用原有数据目录和已保存的模型配置启动新后台。模型为现有 `glm-5.3-flash` / Responses。未修改 URL、key 或模型配置。

只发送一条约350字的通用 GPU 指标解释请求，未调用工具。通过真实 HTTP SSE 客户端记录网络上收到的增量事件，结果如下：

| 指标 | 实测 |
|---|---:|
| 首段非空文字到达 | 4,472 ms |
| 完整回复结束 | 11,200 ms |
| 内容更新次数 | 136 |
| 完成前收到的内容更新 | 136 |
| 工具调用次数 | 0 |
| 最终状态 | completed |

首段已包含7个字符，之后持续增长至491个字符；真实模型首字前仍需要等待，不以打字动画掩盖延迟。以上只是一条真实请求，不是通用速度承诺；网络增量记录不等于像素呈现时间。

原始时间/字符数样本位于本机 `work/ai-live-validation/real-stream.json`，不含 API key 或完整历史消息。用户已要求停止此前的大范围验收，本次没有重复真实 SSH 或跨机器测试。

按用户要求，优先验证网页版，确认功能后再考虑桌面适配和安装包。本轮使用 ChatGPT App 内置浏览器打开原有本地服务，保留原模型配置，没有重复 SSH 检查。

- 从网页发送8条通用解释请求，先观察到第1条的不完整文字和“正在接收回复…”，随后观察到第7条仍在增长；最终8条完整，耗时11.4秒。文字在生成过程中已经进入页面，并非结束后一次显示。

- 点击“取消本轮”，页面显示“已取消”，输入框恢复可用，已接收的第1至第8条片段保留。
- 取消后的页面截图保存在本机 `work/ai-live-validation/web-stream-cancel.png`。以上是实际网页 DOM 和截图验证，不是桌面安装包验证。
