# 在工作台中使用 Codex

AI 助手的「执行引擎」可以选择内置助手或本机 Codex。内置助手继续使用工作台保存的模型接口；Codex 使用本机安装的 CLI 和其登录状态，不读取或复制登录凭据，也不需要给工作台另填 API key。

先安装 Codex CLI，在本机终端运行 `codex login`。助手选择「Codex · 本机 CLI」后即可发送消息。没有找到程序时，可设置后台进程的 `IWB_CODEX_PATH`，指向原生 Codex 可执行文件。Windows npm 安装会解析到包内的原生程序，不执行 `.cmd` / PowerShell 包装脚本。更改环境变量后需重启后台。

工作台通过 App Server 的标准输入输出通信。模型列表来自实时 `model/list`，可以选择模型及其支持的推理强度；未指定时使用 CLI 声明的默认模型。实际模型显示在回复上方；不会沿用工作台 API 配置，也不会静默切换账号。首次发送和模型失败时需检查 CLI 登录、网络及服务可用性。

## 服务器工具与范围

当前原生宿主要求 CLI **0.167.0 或更新版本**；不兼容协议会明确报错。CLI 更新后仍需核对实际能力，版本号不能代替模型、插件及工具实测。执行模式与规划模式可在引擎设置中切换；规划模式用于讨论和结构化提问，不改变权限模式。

每轮创建一个只监听 `127.0.0.1` 的临时 MCP 服务，用随机令牌认证，复用内置助手的工具目录、参数校验、机器范围和本轮技能快照。`get_ssh_info`、`get_ssh_password` 不在此目录。任务结束后关闭监听与连接；令牌不写入聊天、设置或日志。

## 本机项目与原生能力

Codex 使用原生执行循环处理本机命令、文件编辑及子 Agent，不经过 Deep Agents。工作目录可指定为本机绝对路径；未指定时使用工作台创建的持久空白目录。工作目录提供项目上下文，完全访问模式下不构成目录沙箱。原生命令、输出、文件变更、计划及子 Agent 状态记录在当前回复中，不展示模型私有思维链。

机器勾选范围只约束工作台 MCP。拥有本机 Shell 的 Codex 能自行运行 ssh 或访问当前系统账号可读的文件，因此不能把机器勾选范围视为所有原生命令的安全边界。工作台 MCP 仍不提供 SSH 密码工具，并继续执行服务端范围和参数校验。只读模式也不等于禁止所有网络副作用。

按需批准、只读和完全访问分别映射到 CLI 的原生权限策略。按需请求显示命令、目录、原因或文件变更，并等待当前运行的决定；拒绝、取消、断线和后台重启不会自动批准。结构化问题在同一请求中等待选项或文本答案，不以空答案结束后再另起一轮。CLI 版本不支持的请求应明确失败，不能静默放权。

工作台 Skills 通过本轮快照及 `list_skills` / `read_skill` 提供，读取后保留版本记录；CLI 技能另外显示来源。全局 MCP 和插件不静默全量继承，仅使用用户明确选择且当前 CLI 支持的扩展，不修改全局配置。原生子 Agent 的实际可用性及 MCP 继承以当前 CLI 的事件和验证结果为准。

会话同时绑定工作目录、模型选项、权限、机器范围、技能版本和扩展选择；边界变化时创建新 thread，保留已有审计记录。旧隔离模式 thread 不继续使用。相同边界才恢复 thread。切换引擎不会撤销已执行操作。

运行时可点击“补充指令”向当前 turn 发送 steer。补充内容单独显示，不增加对话轮次，也不改变冻结的权限、范围或技能快照。若本轮结束、取消或尚未就绪，服务端拒绝发送并保留输入。取消会中断当前执行并关闭桥接；已启动的远端持久任务仍需使用工作台任务工具显式停止。

## 当前宿主验证

按需模式采用 CLI 的 `workspace-write` / `on-request`，沙箱允许的命令和修改可以直接执行；CLI 请求扩大权限时才显示批准卡片，并非每条命令都询问。待审批和提问最长等待 30 分钟，不受普通模型两分钟无事件超时影响；整轮仍有总时限。原生文件审批缺少完整差异时不批准。

只读模式不允许选择原生额外 MCP 或插件，因为这些服务的远端写操作不受本机沙箱保护。通过工作台高级设置连接的外部 MCP 仍经过共享权限层。当前支持原生联网搜索和本机图片读取；浏览器、电脑控制、图像生成尚未开放，不承诺与 Codex 桌面产品全部功能一致。

命令输出在聊天中预览前 32,000 字符，可按页继续读取，单项最多保留 1 MiB UTF-8 输出；达到上限明确标为截断。聊天删除和七天历史清理同时清理对应输出文件。分支保留原工作目录和可读取的历史输出，不复制或回滚项目文件。

2026-11-07 的 Codex 内置浏览器验证使用独立临时数据、8895 端口和新建空白对话，选用 `gpt-6.1-sol`，观察到原生命令和输出记录及最终 `IWB-UI-NATIVE-OK` 回复，整轮 22.247 秒。会话与测量记录单独保存在忽略的 `work/codex-host-ui-validation.json`。没有连接真实服务器或操作系统窗口。

运行 `.venv/Scripts/python.exe scripts/validate-codex-host.py`，可用 `--model`、`--effort`、`--timeout` 和 `--output` 调整验证；重复 `--scenario` 可只运行指定项目（续聊项需要同时运行前面的 MCP 项）。脚本使用临时项目、隔离 `IWB_DATA` 和合成服务器/技能工具，不连接生产 SSH，不登录、不复制凭据、不修改全局配置。它使用已有 CLI 登录并产生实际模型用量。

报告默认写入 `work/codex-host-validation.json`，分别记录 `verified`、`not_verified` 和 `failed`。命令、文件、原生子 Agent 的 MCP/技能继承、续聊、结构化提问、审批拒绝、steer 及取消必须依据实际事件判断；缺少事件或模型未调用工具不能视为通过。steer 接受成功不代表最终指令已执行。Windows 实测不代表 macOS 已验证。

2026-11-07，Windows / CLI 0.167.0：实际验证了原生命令输出与测试文件读写、`apply_patch` 创建文件及 `fileChange` 差异事件、父 Agent 调用合成 MCP 并读取技能版本、同 thread 续聊，以及原生子 Agent 调用同一合成 MCP 的 `list_hosts` / `read_skill`。子 Agent 结果有不同于根 thread 的 `mcpToolCall` 事件，不只依靠汇总工具记录推断。还验证了原生请求允许和拒绝、steer 接受，以及取消后合成工具终止、活动连接清理和本轮 CLI 进程退出。没有连接生产 SSH。

首次默认模式下，模型未发出结构化提问请求。随后在显式 Plan 协作模式下，使用模型 `gpt-6.1-sol` 实际验证了一个原生结构化问题、同请求回答及最终答案标记。协议桥支持请求不代表默认模式下模型也能调用；普通文本提问不能代替结构化请求。后续还在子 Agent 的合成 MCP 调用阻塞时取消根 turn，确认该工具取消、活动连接清理及本轮 App Server 进程退出；这不保证清理已脱离进程树的任意后台任务。其他扩展、macOS及原生系统窗口尚未由本次脚本验证。

## 历史隔离适配器验证（2026-11-03）

以下记录针对旧版受限适配器，不能用于证明当前完整宿主能力：

2026-11-03：使用本机 Codex CLI 0.147.0 和现有 ChatGPT 登录，实际验证了 App Server 初始化、账号状态、实时默认模型及临时 MCP 的工具发现。发现并关闭了默认启用的电脑控制等环境能力，并用真实目录再次检查隔离。

初次模型试运行返回 `responseStreamDisconnected` / `request timed out`。原因是此机器配置了系统代理，但后台没有对应的代理环境变量。适配器现在只为 Codex 子进程继承操作系统代理；已有 `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` 设置优先，并保留原绕过项、补充回环地址到 `NO_PROXY`，避免把本机 MCP 令牌送往代理。不修改系统代理、全局环境变量或 Codex 配置。

修复后用真实 Codex 模型调用了隔离的 `list_hosts` MCP 工具，返回合成机器别名 `SMOKE-MCP-OK`；恢复同一 thread 后，第二轮未再次调用工具并正确返回这个别名。验证没有连接生产服务器或读取真实凭据。工具执行还需要对本轮工作台 MCP 显式设置默认允许，实际范围和参数仍由工作台校验；其他本机审批保持拒绝。默认模型名称与账号可用性可能变化，以实际 CLI 返回为准。

另一次真实验证未手工提供代理环境，依靠系统代理成功进入合成 MCP 工具；在工具等待期间取消，确认工具被取消、Codex 子进程退出。受控业务任务会先取消并返回 MCP 错误，再关闭 HTTP 监听，避免等待连接超时。

旧脚本 `scripts/validate-codex-integration.py` 对应当时的隔离模式，其历史报告位于 `work/codex-live-validation.json`；当前宿主请使用上面的新脚本。

相关测试：`.venv/Scripts/python.exe -m pytest tests/test_codex_agent.py tests/test_agent_chat.py tests/test_unified_mcp.py -q`。

## 对话分支

对话菜单可从最近一条用户消息之前创建分支，原对话保留。该条消息、终端附件、指定技能和机器范围恢复为草稿；发送前仍重新验证可用机器与技能。运行中的对话需先完成或取消，不能直接分支。

分支仅复制服务端记录的当前机器范围内模型历史，不会从完整界面记录重建模型上下文。它清除 Deep Agents checkpoint、Codex thread 和工具状态；Codex 新 thread 只导入明确绑定到当前范围和引擎的分支历史，最多 60,000 字符，按完整消息舍弃最早部分。旧版本缺少安全快照时不导入模型历史。修改范围或引擎会清除待导入历史。界面可继续显示旧范围的审计记录，这些记录不因此重新传给模型。

分支和补充指令都不会撤销已执行的命令、文件修改或远端任务。需要恢复服务器状态时，应另外明确要求并核对结果。

2026-11-03 的真实 CLI 验证还在合成 MCP 工具等待时调用 `turn/steer`，确认返回相同的 turn ID，再取消本轮并确认工具、进程和活动连接清理。验证仅证明 App Server 接受补充指令；取消前没有等待模型执行补充内容，不声称验证了最终输出。没有连接生产 SSH。

其他本机 CLI 的安装、隔离及验证范围见 [Claude Code 与 OpenCode](EXTERNAL-AGENTS.md)。
