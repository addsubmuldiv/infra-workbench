# Automation workflows

Settings → Automation workflows provides saved, inspectable name/description, bound machines, at most 8 ordered MCP tool calls, manual run, editing, deletion, activation, cancellation and the latest 100 run records. Machine names are selectable; exact tool arguments remain visible. AI can list/create/update drafts using the bundled manage-automation skill and MCP tools; it cannot run or activate a workflow.

The explicit allowlist is in backend/automation.py. Each step must contain a host_id in the saved binding. Save and execution both validate current inventory, caller scope and the business tool JSON schema. Execution uses WorkbenchMCPService.scoped with server-bound machine IDs. Credential tools, skill installation, recursive automation, arbitrary imported code and dynamic evaluation are excluded. Commands remain subject to existing command tool protections and user authorization.

Saving/editing disables triggers. Activation is only through the UI and is deliberately not persistent across application restart. Trusted terminal server channel events supply onConnect/onOutput; no browser event ingestion endpoint exists. Output triggers support only read-only tools. Literal matching uses scrubbed per-session buffers capped at 4096 characters, consumes occurrences, and never persists terminal output. Closing the terminal drops its buffers. A 60-second minimum cooldown, one concurrent run per workflow and two globally bound executions. A workflow cannot create terminal sessions or invoke another workflow.

Steps stop on failure, partial/unknown results and unresolved background jobs or transport handoffs. Completed command jobs may advance; unresolved jobs expose awaiting_job and scrubbed output containing their job ID. No blind retries. Each tool invocation has a 120-second local timeout; a timeout does not establish whether remote work stopped. Cancelling a workflow stops subsequent steps only. Existing remote jobs may continue and must be checked/cancelled through command job tools with explicit user intent; no rollback is implied. Restart marks unfinished local runs interrupted. Run outputs are credential-scrubbed and capped at 12000 characters per step; only 100 runs are retained.

Validation: synthetic tools, in-process MCP and local terminal tests; no production SSH writes. JSON step editing is intentionally explicit: no variables, conditionals, arbitrary code or automatic job continuation in this version.
