# 优化后网页版与桌面版的实测对比

测试日期：2026-10-31。平台：本机 Windows 11，i5-13600KF、20 个逻辑处理器、约 64 GiB 内存。

**本次结果：桌面版有小幅的独立客户端内存优势，但没有显示启动或多终端速度优势。浏览器已经运行时，新开网页的新增成本更低。**

## 测试方法

- 两端加载同一份冻结的生产前端构建，1440×900 内容视口、48 台模拟机器、384 个设备；前端 SHA-256 保存在汇总数据中。
- 网页使用独立配置目录的可见 Edge 窗口，禁用扩展；桌面使用优化后的 Tauri 构建。桌面测试构建只改变应用标识/产品名，用于隔离单实例和窗口状态，不改变 UI 或业务代码。
- Edge 版本为 `156.0.4314.42`，WebView2 为 `156.0.4314.50`。主版本一致，补丁版本不同，因此不能把小幅差异直接归因于 Tauri 或 Rust。
- 本地测试服务通过仅对子进程生效的代理提供相同页面和数据，没有更改系统代理。Python 后台预先就绪，两端复用的后台不计入客户端差值；本测试不包含首次 Python 解包或后台启动成本。
- 两端均传入相同的禁用后台/遮挡节流参数；启动复测记录检查了视口、可见状态和相同的设备像素比例。没有清空操作系统文件缓存，也没有把数据称为重启电脑后的冷启动。
- 先做短测校准，再交替运行三个正式轮次。每轮分别测试 4 个终端、每个 64 KiB/s、持续 45 秒；8 个终端、每个 128 KiB/s、持续 60 秒。
- 使用真正的本机 WebSocket 连接向真正的 xterm.js 输入带 ANSI 颜色的固定训练日志。每个终端最多允许 8 个未回执消息，与现有后端的流控窗口一致。这里隔离了远端 SSH、网络和训练程序的波动，并不代表真实 SSH 网络吞吐上限。
- 持续输出时轮换点击真实终端标签，测量 pointerdown 到标签选中后两帧的延迟；同时记录帧间隔、长任务和输出写入回执。

## 启动速度

从启动客户端进程，到机器列表出现、字体就绪且经过两帧后，测试服务收到就绪信号。

启动单独进行了一组严格复测：每次确认宿主、渲染和 GPU 等测试子进程全部退出后，再启动下一次。早期快速重开组的桌面波动较大，不作为下面表格的主结论。

| 场景 | Edge 网页版 | Tauri 桌面版 |
|---|---:|---:|
| 后续独立启动，5 次中位数 | **0.97 秒** | **1.77 秒** |
| 同组最小—最大值 | 0.81—1.50 秒 | 1.61—2.11 秒 |
| 全新浏览器/WebView 配置首次打开，单次 | 1.42 秒 | 1.29 秒 |
| 已有空白浏览器窗口，新开工作台页，5 次中位数 | **0.46 秒** | 不适用 |

新配置首启只有一次，且操作系统文件缓存已经被之前的测量预热，不能用这一个样本认定首启谁更快。后续独立启动的五次结果中，桌面版约多用 0.80 秒。

## 内存占用

统计整个客户端进程树，而不只统计 Rust 外壳或某个页面进程。主要指标为 **私有工作集**，避免把各进程共享的 DLL 页面简单重复相加；另记录私有提交内存作为补充。两者含义不同：[微软进程内存计数说明](https://learn.microsoft.com/en-us/previous-versions/aa394323%28v%3Dvs.85%29)、[工作集说明](https://github.com/MicrosoftDocs/win32/blob/docs/desktop-src/ProcThread/process-working-set.md)。

下表为三个轮次的中位数，单位 MiB（1 MiB = 1,048,576 字节）。空闲阶段每轮取三次进程树采样；输出阶段在持续输出中多次采样。

| 场景 | 网页版私有工作集 | 桌面版私有工作集 | 桌面少占 |
|---|---:|---:|---:|
| 资源总览空闲 | 218.07 | 193.27 | 24.80，约 11.4% |
| 4 终端持续输出 | 438.67 | 426.31 | 12.36，约 2.8% |
| 8 终端持续输出 | 525.98 | 507.39 | 18.59，约 3.5% |

空闲私有工作集的轮次范围：网页 201.48—226.38 MiB，桌面 192.71—225.78 MiB，范围有重叠，不能承诺每次桌面都更省。8 终端范围分别为网页 509.37—528.91 MiB、桌面 502.73—509.33 MiB。

对应的私有提交内存中位数：空闲为网页 413.77 / 桌面 376.61 MiB；4 终端为 617.09 / 563.71 MiB；8 终端为 693.10 / 651.44 MiB。这些数字不能当作当前实际驻留的物理内存。

另测“浏览器已经开着”的情况：独立空白 Edge 窗口为 118.02 MiB，加入工作台页后为 211.50 MiB，新增约 **93.48 MiB**。此场景中，新增网页页签的成本低于另起一个约 193 MiB 的桌面客户端。该增量来自一次基线/加载后的三点采样，不等同于对用户现有所有标签和扩展的测量。

## 多终端持续输出

表中延迟为三个轮次各自 P95 的中位数，不是平均耗时。输出写入延迟是从测试服务发送数据，到 xterm.js 的 write 回调发回 ACK，包含本机传输、解析和调度，不等于字符最终出现在屏幕上的时间。

| 指标 | 网页 4 终端 | 桌面 4 终端 | 网页 8 终端 | 桌面 8 终端 |
|---|---:|---:|---:|---:|
| 实际接收吞吐，KiB/s | 255.73 | 255.82 | 1023.73 | 1023.63 |
| 输出写入回执 P95，ms | 4.85 | 4.52 | **7.14** | **15.83** |
| 切换终端呈现 P95，ms | 19.3 | 25.0 | **20.4** | **28.8** |
| 页面帧间隔 P95，ms | 4.3 | 4.3 | 4.3 | 8.3 |
| 客户端平均 CPU，等效单核数 | 0.69 | 0.87 | 0.88 | 1.10 |
| 测到的 >50ms 主线程长任务 | 0 | 0 | 0 | 0 |
| 结束后未回执消息 | 0 | 0 | 0 | 0 |

三轮 8 终端测试中，两端分别处理约 180 MiB 输出，所有发送的有效载荷字节均获得回执。十二个负载阶段均没有非预期断连、标签切换失败或回执积压。日志历史仍按现有终端的 5000 行滚动缓冲规则保留；收到回执不表示无限保留所有历史输出。

CPU 的“等效单核数”是进程树 CPU 时间增量除以采样墙钟时间；例如 1.10 表示约 1.1 个逻辑核的持续工作量，不是整台 20 线程电脑的 110%。每组 CPU 的轮次范围有明显重叠，不能把 0.22 核的中位数差当作稳定常数。

8 终端下，网页的写入 P95 范围为 6.42—12.10ms，桌面为 13.93—18.32ms；切换标签 P95 范围分别为 15.5—23.3ms、22.7—34.0ms。本次高负载下桌面没有速度优势，部分延迟更高；两端在设定速率下都能持续完成处理，尚未测量各自的吞吐极限。

## 对当前软件的判断

桌面版目前适合作为独立窗口入口。相对于再开一个完整浏览器实例，私有内存少了十几到二十几 MiB；但不能据此称为明显的性能升级。已经使用浏览器时，网页的新页签方式更快、额外内存更少。

后续若要提升共同的流畅度，应继续从共享页面与终端渲染路径找瓶颈。现有测量没有支持“换成 Rust 外壳，前端就会明显更快”这一判断。macOS 的 WKWebView 未参与本次测试。

准备测试依赖和隔离的优化构建：

```powershell
npm.cmd install --prefix work/desktop-benchmark --no-save ws@8
npx.cmd --yes --package @playwright/cli playwright-cli --help
@{identifier='com.infra-workbench.benchmark';productName='Infra Workbench Benchmark'} |
  ConvertTo-Json | Set-Content work/desktop-benchmark/tauri.bench.json -Encoding utf8
$previousBenchmarkTarget=$env:CARGO_TARGET_DIR
Push-Location desktop
try {
  $env:CARGO_TARGET_DIR=Join-Path (Get-Location).Path 'src-tauri/target/benchmark'
  node node_modules/@tauri-apps/cli/tauri.js build --no-bundle --config ../work/desktop-benchmark/tauri.bench.json
} finally {
  $env:CARGO_TARGET_DIR=$previousBenchmarkTarget
  Pop-Location
}
```

先启动原有后台，确认 `http://127.0.0.1:8765/api/health` 可用。然后在项目根目录运行测试与汇总入口（最后两行需替换为脚本输出的实际目录）：

```powershell
node scripts/benchmark-desktop.cjs --smoke
node scripts/benchmark-desktop.cjs
node scripts/benchmark-desktop.cjs --startup-only --snapshot=此前正式测试目录/frontend
node scripts/summarize-desktop-benchmark.cjs 正式测试目录/results.json 启动复测目录/results.json
```

脚本仅操作本次启动的测试客户端。测试窗口、进程和本地测试服务已关闭；原有 Python 后台继续运行。产品代码、真实主机配置和真实终端任务没有在本次测试中修改。
